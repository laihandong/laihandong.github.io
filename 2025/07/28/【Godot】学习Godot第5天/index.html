创建场景

注意看，软件左侧有创建根节点（Create Root Node）的窗口和几个选项，随便选一个创建并保存，如有需要可以重命名一下。另一种创建方式，在编辑器左下角的文件栏，可以右键菜单中创建场景，新场景会自动加载到编辑器中，编辑器中间窗口也可能会发生变化。

我们刚刚添加的是一个节点。这些节点代表 Godot 中的一切。图像、声音、菜单、特效——所有这些都是节点。你可以将它们视为游戏对象，每个对象在游戏中都有其独特的功能。玩家可以是一个节点，就像敌人或金币一样。

另一方面，场景是节点或游戏对象的集合。目前，你可以将场景视为关卡。对于一个关卡，你需要一个玩家节点、一些敌人节点和许多金币节点；这些集合构成一个场景。节点就像颜料，场景则是我们的画布。

节点和场景，场景和节点，这是贯穿Godot游戏开发过程的话题。场景是一个可以执行的独立文件，它包含一组节点组成的节点树，仅有一个根节点。有多个场景的存在下，若要运行当前场景，点击右上角项目调试运行一栏的第五个按钮（运行当前场景F6）。

简述编辑器界面

刚安装，没有更改布局的话，UI应该如下描述：
左上：场景树区域，显示当前场景中的所有节点
左下：文件系统区域，提供了对项目文件夹内文件的访问
中间：当前活动的主编辑器。比如 2D 编辑器——可以在场景中的 2D 空间放置节点。
右侧：检查器（Inspector）区域，显示当前选中节点的属性。脚本（GDSript）也可以作为属性，添加给节点，用来拓展节点的功能。

给节点添加脚本

一个比较基础的操作，就是只需要在场景树区域右键某个节点，在右键菜单中选择添加脚本，填好设置再点确定即可。
这就不得不q一个经典的例子啦：尝试在_ready()函数体内（记得缩进），编写代码print(“Hello World”)，然后保存并运行项目，这样你将会在编辑器的底部输出栏看到打印出的Hello World字样哈哈哈。

变量、数据类型、流程控制等等

变量及命名

玩家所控制的角色的位置、队友的名字、音量大小、buff最大持续时间、玩家右键鼠标在屏幕上的位置等等数据片段都可以用变量表示。这很基础，是的，需要注意一下游戏工程中，变量的命名有些技巧可以使用、也有些基础的注意事项：

一是变量名不能有空格，只能由字母数字和下划线字符组成，且不能以数字开头，这串字符是合法的字符的集合abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ1234567890_；二是变量名最好不要和内置关键字重名；三是推荐使用snake_case风格来给变量命名；四是推荐使用描述性的名称，比如number_of_lives来命名角色有几条命，而不是用lives、l或shengmingzhi等等。不用担心变量名的长度，担心担心过了一周甚至一月你还能不能看懂你的数据和怎么用它最重要，再强迫症也要在此基础上才去精简；

然后，在GDSript中，最通用的是以var关键字来声明变量，比如var number_of_lives = 5，这里顺便用等号赋值了个5给它。这里的等号可以理解一个动作，把右边的值赋给左边的变量，这与数学里的表示两边相等的等号意义不同（刚学计算机时，我在这老是没转过弯）。再举例一个很简单的受击后计算生命值：number_of_lives = number_of_lives - damage，等价的简化版是这样：number_of_lives -= damage。所以，再多认识些运算符GDScript reference — Godot Engine (stable) documentation in English，这小节就算过了。

常量

其实也可以归为变量，一种在程序执行过程中，你不能改变它的特殊变量。其实就是（语言设计之初时）主观上的用法划分，不然和变量没什么区别，关键字是const。在命名上，所有字母大写，且同样snake_case风格。

常量有个好处，就是将一些零零散散的数字，用命名将其更方便代码的阅读和理解，同时也使代码整洁。比如number_of_lives -= 5和FIRE_BALL_DAMAGE = 5 number_of_lives -= FIRE_BALL_DAMAGE的区别

数据类型

整数-9223372036854775808 and 9223372036854775807（64位二进制表示范围）

浮点数（包含小数点的数字），GDScript 中的浮点数精度最高可达 14 位小数

整数可以存储在浮点数中，只要它们足够小，就不会有问题。然而，当我们把浮点数存储在整数中时，小数点后的所有内容都会被丢弃！这被称为隐式类型转换，因为我们隐式地将浮点数转换为整数。

而且，由于计算机总会在某个时刻对小数进行四舍五入，即无法精确表示每一位可能的数，我们不得不在有些特殊的场景，留意这个问题。不过但多数时候，我们不需要担心。

字符串
非数字的数据类型，可以理解为文本。在GDScript中，用一对双引号或一对单引号括起来表示，在范围上覆盖了所有的Unicode字符。字符串没有长度限制，只要你/玩家电脑内存装得下。

面向对象编程

面向对象编程有四个关键原则，抽象、封装、多态和继承，但实际应用中远不止如此，尤其是游戏编程。

这里的抽象，更多是指一个类隐藏其内部实现，仅通过暴露高级函数来抽象其功能，常用做法比如划分私有公有成员。然而，在 GDScript 中，没有明确的方法来标记变量或函数为公共或私有。一切默认为公共，并且可以被外部世界访问。但GDScript 将下划线（_）放在预期为私有的变量和函数名称前，表示一个变量或方法是私有的，不应该被类外部任何东西使用。但，你还是可以用的哈哈哈，不过那会非常难看，极不推荐。

封装和抽象类似，是抽象的延伸，专注于类的数据。外界越少直接处理类的成员变量，而更多地处理成员函数，就越好。

多态、继承和方法重写、变量覆盖，这都是一整套的，移步更专业的介绍。

代码整洁

很多人说这优先级不高，先把功能做出来再说。我觉得，至少也得了解一些基本的代码整洁原则，习惯使用它们，然后贯穿整个编码过程，而非搞个谁先谁后的顺序。我可不想昨晚某个功能，在几个月后又得花好几天的时间去看懂它们。

命名规范

主要讲变量（常量）、函数和类（节点）的命名：
变量和函数用snake_case风格；常量用SNAKE_CASE风格；类（节点）用PascalCase风格。我建议使用这一套，让团队所有人都用着顺手才好。

函数也可以看成变量，所以命名规范一致。

命名是有技巧的：

意义和描述性

有些人说短变量名会导致游戏性能更好，但在现在，这纯属无稽之谈。编程语言会在代码中对变量进行标记化处理，使得任何变量名称的执行速度都相同，无论多长。所以我们要做的事情之一，在于让变量的、方法的或类的名称具有意义和描述性。如何做到这点呢？可以在命名前，完成下列问题清单：

  • 变量：
    • 变量将包含什么类型的数据
    • 这份数据应该如何使用
  • 函数：
    • 函数的作用是什么
    • 函数返回什么数据
    • 函数需要什么类型的参数才能工作
  • 类：
    • 类将用于什么
    • 类负责哪些数据

减少填充词

比如the、a、object，不然只会徒增长度

保持名称易于发音

就像读书一样，不要老整些晦涩难懂的高级词汇，就算是缩写，也用最常用的，大家都看得懂的，但尽量还是用完整单词。

保持一致性

整个项目的命名风格应该一致，就算有时违反了你一贯的风格，也要一致地违反下去。

公有私有

明确指出类的哪些成员是私有的且不应被访问仍然非常重要。这将帮助你自己或其他后续使用该类的程序员。

编写短函数

一个函数尝试做的事情越多，该函数内的代码就越多，理解它所做的事情就越困难。因此，为了保持函数易于理解，一个很好的经验法则是将行数控制在 20 行以内。这样你可以快速理解发生了什么以及如何有效地使用该函数。

当然，你可以调用不同的函数。将长函数拆分成多个具有良好描述性名称的小函数将为你节省许多时间来弄清楚代码的作用。 游戏项目中，这很常见。比如之前负责过的上线项目，游戏启动的主流程全部编写在一个main函数中，但里面90%的内容都是对其他函数的调用，一眼就能看出整个游戏背后的大致流程，也方便排查bug。

不要重复代码（DRY）

当然，若非设计如此，尽量不要有一模一样的大段大段的代码出现在同一项目中。而应该只编写一次代码，然后尽可能多地重用它。

上面提到“设计如此”，我指的是，有时候，针对特定场景量身定制的重复代码是没问题的（比如某些解耦合的设计），而不是将多个场景硬塞进一个代码片段中。

只做一件事（KISS）

将解决方案保持在最简状态，这意味着不要解决还不存在的问题。这样，你不会开发不需要的功能，也不会浪费时间创造没人会使用的东西。（我就经常会考虑没发生的事，但实际上在项目组其他人，特别是领导看来，你就是在摸鱼和磨洋工，产出少。）

总之，不要让你的代码变得复杂。复杂的代码难以维护和理解。

防御式编程

你通过尽可能检查代码中的各种情况和边界条件来确保安全。例如，在函数中，你可以在函数开始时检查参数是否正确。这样，你将长期避免许多报错。
就算你不这样做，你也会被游戏测试逼着这样做的哈哈哈，他们最喜欢测这种边界条件了。

编程风格

这里推荐参考参考GDScript官方的风格指南GDScript style guide — Godot Engine (stable) documentation in English
不是说全部照搬，而是一点一点去搬，去慢慢融入到你个人的编程习惯，并推广到全项目组。

空格（和换行）

尽量把按空格这个习惯，养成跟呼吸一样自然，因为GDScript中貌似没有一键风格化。

还有换行，逻辑相同的成一组，不同的用行隔开。

合理使用空格、换行，看起来真的会舒服很多。

行长度

不要太长了，最长不要超过你的竖屏显示器的宽度就OK。

利用文档

Godot编辑器内置文档

ctrl+鼠标左键单击，可以访问任何内部类的文档，也可以跳转到函数或变量的定义处。

按F1或编辑器中间窗口的右上角“搜索帮助”，可以输入任何你想搜索的类、函数或变量。
